# 多語系（I18N）

tokaDiscordLink 0.2.0 起，所有使用者看得到的文字都放在共用套件 [tokaI18n](https://github.com/zisunny104/tokaI18n)（內嵌進 jar，重新定位到 `dev.toka.discord.internal.i18n`）的語系檔 `src/main/resources/lang/zh-TW.yml`。目前只有繁體中文，語言由 `config.yml` 的 `language`（預設 `zh-TW`）決定。伺服器擁有者可把同名檔放進 `plugins/tokaDiscordLink/lang/`，只寫要覆蓋的 key。

已抽出 **77 個 key**（77 個文字，其中 3 個是多行清單）。程式碼裡不再有中文字串（註解除外），測試 `LanguageFileTest` 會檢查：檔內每個 key 都能讀到、原始碼引用的 key 都存在、原始碼沒有中文字面值、`/discord help` 列出所有子指令。

## 分區

| 區 | key 數 | 內容 |
|---|---|---|
| `cmd.discord.*` | 3 | `/discord` 簡述、玩家用法、管理員追加的用法 |
| `help.*` | 2 | `help.discord`（所有人）、`help.discordAdmin`（管理員追加） |
| `msg.*` | 19 | 綁定、解除、查看、`/discord status` 各行 |
| `err.*` | 13 | 權限不足、格式錯誤、代碼錯誤、綁定衝突等 |
| `log.*` | 13 | 後台日誌 |
| `status.*` | 12 | 狀態字、停用原因、失敗原因（會嵌進別的訊息，不含色碼） |
| `discord.*` | 15 | 送到 Discord 的文字：斜線指令說明、`/link`、`/unlink` 的回覆、未知指令預設回覆 |

## 每個指令的 help

| 指令 | help 位置 |
|---|---|
| `/discord help` | `help.discord`（所有人看到，含 `link [代碼]`、`unlink`、`info`、`help`） |
| `/discord help`（管理員追加） | `help.discordAdmin`（`status`、`link <玩家> <Discord使用者ID>`、`unlink <玩家>`、`info <玩家>`；OP 或後台會看到） |

Discord 端 `/link [code]`、`/unlink` 的說明就是斜線指令的描述（`discord.cmd.link.desc`、`discord.cmd.link.code`、`discord.cmd.unlink.desc`）。指令名稱 `link`、`unlink` 與參數名稱 `code` 不翻譯。

## 顏色套用對照

| 類型 | 套用 |
|---|---|
| 遊戲內一般訊息 | 主文字 `§b`，變動值（代碼、分鐘、數量、ID）`§a` |
| 成功 | `§a`（綁定完成、已解除綁定） |
| 錯誤、拒絕 | `§c` |
| 用法、次要說明 | `§7` |
| help | 標題 `§6§l`，指令 `§e`，說明 `§b` |
| 後台日誌 | 不加方括號標籤（原本的 `[綁定]` 已移除）；文字 `§b`、數字 `§a`、警告 `§e`、成功 `§a`、錯誤 `§c` |
| 送到 Discord 的文字 | 不用 `§` 色碼，只用 Discord 的 Markdown（`**粗體**`） |
| 狀態字（`status.*`） | 不含色碼，嵌進其他訊息後由外層決定顏色 |

## 不翻譯、不搬進語系檔的東西

- 指令名稱、權限節點、config 欄位、Discord 斜線指令名稱與參數名稱、暱稱模式代碼（`off`／`set`／`enforce`，顯示的是設定值本身）。
- `config.yml` 內管理員自訂的文字：`status`、`unknown-command-msg`、`bot-start-msg`、`bot-stop-msg`（維持在 config）。`discord.unknownCommand` 只是 config 沒有該欄位時的預設。
- 例外的英文訊息（給開發者看）、`NukkitSlf4jLogger` 的橋接日誌。
- `plugin.yml` 的指令說明、用法（補上 `help`）與權限說明維持繁體中文（Nukkit 在載入時讀取，不經過語系檔）。

## 待確認

1. **`discord.*` 區**：慣例表沒有「送到 Discord 的文字」這一區，暫用 `discord.*`（不含 `§` 色碼）。是否要納入共用慣例？
2. **log 色碼**：`log.storageOpenFailed` 用 `§c`（原本無色，且是 error 等級），慣例表沒有後台錯誤色，請確認。
3. **管理員追加的 help**：`help.discordAdmin` 是與 `help.discord` 分開的第二個 key，慣例是 `help.<指令>` 單一清單；為了讓一般玩家看不到管理員子指令才拆開。
4. **`/discord help` 是新子指令**：原本 `help` 會落到用法提示；用法與 `plugin.yml` 的 usage 因此多了 `| help`（補 help 的預期變更）。
5. **`msg.status.permission`**（「權限串接：等待中…」）用 `§7`，因為它是備註不是警告；若要視為警告請改 `§e`。
6. **`cmd.discord.desc`** 目前沒有程式使用（`plugin.yml` 靜態說明已有），留作 help／其他插件查詢用，若不需要可刪。
7. 遊戲內玩家訊息原本全無顏色，現在依慣例上色，這是顏色套用造成的可見差異。
8. Discord 端 `/link` 回覆提到「請在遊戲裡輸入 /discord link …」，指令名稱本身寫在文字裡，若日後指令改名需要同步改語系檔。
